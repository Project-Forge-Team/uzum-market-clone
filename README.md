# Uzum Market — учебный клон

Учебно-портфолиошный клон маркетплейса: каталог, карточка товара, корзина, оформление
заказа, отзывы — и **полный путь продавца**: публикация товаров, управление остатками,
заказы и ответы на отзывы. Всё работает по-настоящему, но на локальной «базе данных»
без внешнего бэкенда и без платежей.

> Это не официальный Uzum. Дизайн и контент — упрощённая самодеятельность «по мотивам»,
> тексты и «фото» товаров сгенерированы. Никаких данных реальных пользователей и
> настоящих эквайрингов здесь нет.

## Стек

- **Next.js 16 (App Router) + React 19** — серверные компоненты для каталога и карточек,
  клиентские — для интерактива (корзина, отзывы, фильтры, форма товара)
- **TypeScript (strict)** — общие DTO в `types/product.ts` для API и клиента
- **Tailwind CSS v4** — токены бренда в `app/globals.css` (`@theme`)
- **route handlers** — своё API в `app/api/**`, без внешнего Django/Supabase
- **Файловое хранилище** — `lib/server/db.ts`: JSON-«БД» в `.data/db.json` (атомарная
  запись + сид из `lib/server/catalog.json`), пароли — `scrypt` с солью
- **react-hook-form + zod** — валидация входа, регистрации, отзыва и карточки товара

## Запуск

```bash
npm install
npm run dev          # http://localhost:3000
```

При первом запросе создаётся `.data/db.json` с демо-каталогом (10 категорий,
10 магазинов, 42 товара, 84 отзыва). Пересобрать сид:

```bash
node scripts/gen-catalog.mjs   # пишет public/products/gen/*.svg + lib/server/catalog.json
```

Демо-аккаунты (пароль у всех `Password123`):

| Роль | Логин | Что смотреть |
| --- | --- | --- |
| Продавец | `seller@uzum.uz` | магазин «Uzum Students»: товары, заказы, отзывы |
| Покупатель | `buyer@uzum.uz` | заказ `UZ-100246` с историей статусов и отзывы |
| Техно-магазин | `electro@uzum.uz` | магазин Electro House |

На страницах входа/регистрации есть блок «Демо-аккаунты» — клик заполняет форму.
Сбросить данные: **Профиль → Настройки → «Сбросить демо-данные»** (или `POST /api/demo/reset` —
только для вошедшего аккаунта; на публикации кнопка выключается переменной `UZUM_LOCK_DEMO=1`).

чернового товара тоже уходит в 404 (владельцу черновик виден с предупреждающей плашкой).

## Механика, которая реально работает

- **Товары продавца.** `POST /api/products` → товар появляется в каталоге, поиске,
  категории и на витрине магазина. `status: draft` скрывает его от покупателей,
  `archived` — снимает с продажи; удалить — значит удалить и отзывы о нём.
- **Заказы.** Суммы считает сервер: доставка 0 при самовывозе или от 500 000 сум,
  иначе 25 000; промокод `STUDENT10` (−10%, от 200 000), `UZUM2026` (−5%).
  Заказ списывает остатки, получает номер `UZ-1xxxxx` и историю событий; отмена
  возвращает остатки на склад.
- **Отзывы.** Один отзыв на товар с аккаунта (повторный `POST` обновляет его),
  тексты 15–2000 символов, оценка 1–5, «плюсы/минусы», значок «заказ подтверждён»,
  разбивка по звёздам, ответ продавца. Удалить может автор или владелец магазина.
- **Корзина и избранное** живут в `localStorage` под ключами со scope
  (`u<id>` / `anon`): при входе анонимная корзина объединяется с пользовательской,
  изменения синхронизируются между вкладками, цены и остатки сверяются с API.
- **Загрузка фото.** `POST /api/uploads` (multipart) кладёт файл в `.data/uploads/`
  и отдаёт `/api/uploads/<имя>`; в форме товара картинки можно переставлять и удалять.
- **Сессия.** HttpOnly-cookie `uzum_sessionid` (7 дней) + CSRF-кука `uzum_csrf`,
  которая обязана прийти в заголовке `X-CSRFToken` на всех мутациях.

## API

Локальные route handlers (все — same-origin `/api/*`, ошибки в формате
`{ detail, fields? }`, список товаров — `{ count, page, results, facets, ... }`):

```
GET  /api/categories                     список категорий
GET  /api/products                       ?q=&category=&seller=&min_price=&max_price=&ordering=&page=
GET  /api/products/{id|slug}             карточка (черновики — только владельцу)
POST /api/products                       создать товар (нужен магазин)
PATCH|DELETE /api/products/{id}          редактирование/удаление своего товара
POST /api/products/{id}/status           active | draft | archived
POST /api/products/{id}/view             счётчик просмотров (из client-beacon)
GET|POST /api/products/{id}/reviews      отзывы + сводка; публикация/обновление
DELETE /api/reviews/{id}                 автор или владелец магазина
POST /api/reviews/{id}/reply             ответ продавца
GET  /api/products/mine                  свои товары, включая черновики
GET|POST /api/orders                     превью сумм (PUT) и создание заказа
GET  /api/orders/{id} · POST /api/orders/{id}/status   история и смена статуса
GET  /api/shop · POST /api/shop · PATCH /api/shop      магазин продавца
GET  /api/shop/orders                    заказы с товарами магазина
GET  /api/sellers · /api/sellers/{slug}  магазины и их витрины
POST /api/uploads · GET /api/uploads/{file}
POST /api/auth/register|login|logout · GET /api/auth/me · POST /api/auth/password
GET  /api/auth/csrf · POST /api/demo/reset
```

Локальные обработчики конкретные, поэтому они всегда выигрывают у catch-all
прокси `app/api/[...path]/route.ts`. Прокси при этом живой: любой `/api/*`, для
которого обработчика нет, уходит на `BACKEND_URL` (по умолчанию — старый Django
на Render, отсюда и 502 в песочнице без сети). Именно через него фронт
переключится на настоящий бэкенд — план в `docs/BACKEND_SPEC.md`, §10.

## Проверка

```bash
npm run lint            # eslint (next/core-web-vitals + react-hooks)
npx tsc --noEmit        # типы
npm test                # поднимает app в песочнице и прогон tests/e2e.py (55 шагов)
npm run build           # продакшен-сборка
npm start               # прод-режим на :3000
```

`npm test` ничего не трогает в рабочей копии: демо-база и каталог сборки уезжают
во временную папку (`UZUM_DB_DIR` / `NEXT_DIST_DIR`), порт берётся свободный,
процесс гарантированно убивается. Скрипт идемпотентен — можно гонять подряд
дважды и против уже запущенного сервера:

```bash
UZUM_BASE_URL=http://127.0.0.1:3000 python3 tests/e2e.py
```

## Чего намеренно нет

Платежи и эквайринг, email/SMS-уведомления, реальные фото и тексты брендов,
админ-панель модерации, полноценный поисковый индекс (используется `LIKE` по
названию/описанию/бренду), мультиязычность, отзывы с фото. Это осознанные
упрощения учебного проекта: важнее — сквозная механика маркетплейса.
